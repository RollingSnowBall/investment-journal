# _drafts — 컴파일 전 초고

AI가 만들어 온 글을 여기 그대로 떨어뜨린다. 파일명은 아무거나 좋다 —
진짜 이름은 frontmatter의 `id`가 정한다.

컴파일하면 검증을 거쳐 `posts/`로 넘어가고, 초고는 `published/`로 치워진다.

```bash
python tools/compile.py --dry-run   # 검증만
python tools/compile.py             # 컴파일
```

Claude Code에 "컴파일해줘"라고 해도 된다.

## 이 디렉토리는 배포되지 않는다

GitHub Pages의 Jekyll은 `_`로 시작하는 디렉토리를 결과물에서 뺀다.
그래서 초고는 저장소에 남지만 웹에는 뜨지 않는다. 여기가 사람만 보는 자리다.

## 초고 형식

`index.json`에 들어갈 메타를 본문 앞에 그대로 붙인다.

```markdown
{
  "id": "2026-07-something-here",
  "title": "무슨 일이 있었는지 드러나는 제목",
  "date": "2026-07",
  "tag": "관점정리",
  "tickers": ["TSLA", "GOOGL"],
  "summary": "홈 목록에 붙는 한두 문장. 제목을 반복하지 말고 판단의 이유를 적는다."
}

여기부터 본문. H1(`#`)은 쓰지 않는다 — 제목은 위 메타에서 온다.
```

- 위처럼 맨 앞에 JSON (기본)
- ` ```json ` 펜스로 감싼 JSON
- `---`로 감싼 YAML frontmatter

`index.json`에서 통째로 복사해 와서 `}` 뒤에 쉼표가 붙어도 알아서 뗀다.

`tickers`는 `[]`로 비워도 된다(`되새김` 글).
`tag`는 여섯 개 중 하나: 리밸런싱 · 관점정리 · 관망 · 리서치 · 회고 · 되새김.

여러 편을 한 번에 넣으면 파일명 순서대로 위에서부터 쌓인다.

## 컴파일이 막는 것

- 앞머리 메타 누락, 필드 누락
- `id` 형식 오류, 이미 쓴 `id`, `id`와 `date` 불일치
- 태그 오타나 신설
- 본문에 H1이 있는 경우
- 소문자 티커

## 경고만 하고 넘어가는 것

- 닫는 `**` 앞이 구두점이고 뒤가 한글이라 볼드가 깨질 자리
- 금액처럼 보이는 표현 (공개 저장소다)
- H2가 하나도 없는 글

## 왜 frontmatter를 떼는가

Jekyll은 frontmatter가 붙은 파일을 HTML로 변환한다. 그런데 사이트는
`posts/*.md`를 fetch로 받아 marked.js에 넘기므로 원본 마크다운이어야 한다.
그래서 `posts/`에 들어가는 파일에는 frontmatter가 없어야 하고, 컴파일이 그 일을 한다.
